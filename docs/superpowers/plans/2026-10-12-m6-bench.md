# Coglossa M6 — `coglossa bench`: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `coglossa bench`, the quality evaluation of spec §9.2. It has three parts:
- **Comparison.** It runs any number of Coglossa configurations, plus a single-model one-pass baseline, over FLORES-200. It reports MetricX-24 in reference mode, chrF, tokens and time per system and language pair, and can export a blind A/B sheet for human preference judgments.
- **Flag testing.** It injects known errors into reference translations and measures how often Coglossa's flags catch them, giving recall and precision per tier and per error type.
- **Calibration.** It turns those measurements into suggested thresholds and a `tiers.yaml`.

It runs inside the air-gapped install against the customer's own models, from FLORES data shipped in the bundle. The same tool vets a customer's in-house models today, and will later choose the models Coglossa bundles for customers without their own (Qwen3 and Gemma 3 are the candidates; that decision waits for these results).

Tasks 1–2 carry two items from `docs/m5-followups.md` that the customer would meet at once:
- config errors print on several lines
- Traditional Chinese and Japanese passages show Simplified glyph forms.

**Architecture:**
- **One new package.** Everything lives in `engine/coglossa/bench/`, a library with one module per responsibility, plus a `coglossa bench …` command group. Bench never touches the database. It runs the pipeline in-process (`run_document`), exactly as `coglossa run` does, and writes plain files (JSON, JSONL, Markdown, CSV, YAML) to an output directory.
- **Reuse, not reimplementation.**
  - Systems are translated by the real pipeline. The baseline runs one translator call per chunk through the same `translate` stage code, refactored so one translator can be called alone.
  - Injected errors are scored by the real `score_chunk`. The flags measured are therefore exactly the flags the product raises.
- **Units, not sentences.** A FLORES sentence becomes one paragraph of a plain-text document. Translators may merge sentences across paragraphs, so outputs are compared per *unit*: a maximal run of paragraphs joined by spans. Most units are one sentence.
- **Resumable runs.** Every (system, pair) result is its own file, so a long run on real models resumes where it stopped.

**Tech Stack:**
- **New code:** Python 3.12, pydantic, httpx (already engine dependencies). No new engine dependency; chrF is implemented here (about 40 lines) rather than pulling in sacrebleu.
- **Unchanged:** FastAPI and the scorer service for MetricX reference mode, React/Vite (Task 2), bash and Docker Compose (Task 11).

## Global Constraints

- **Every M1–M5 constraint still holds:**
  - 95% branch coverage per Python package
  - web coverage ≥ 95% on lines, branches, functions and statements
  - `filterwarnings = ["error"]`
  - `make lint` clean
  - `make schema` shows no drift
  - unit tests touch no network except `127.0.0.1`
  - every user-facing message is one line
  - "translation guide", never "bible".
- **Scores are never invented.** A signal or metric that cannot be computed is `null`, never guessed or truncated (spec §1.2, criterion 4). An over-long unit gets `metricx: null`; it is never truncated.
- **Bench never needs the internet at runtime.** Only `coglossa bench fetch-flores` downloads, and it runs on a machine with access. Everything else reads local files.
- **FLORES-200 is CC BY-SA 4.0.** Wherever the data is stored or shipped, its attribution travels with it in a `LICENSE.txt` and `ATTRIBUTION.txt` beside it.
- **Deterministic.** Sentence sampling and injection choices use a seeded `random.Random(seed)` with `seed` from the bench config (default 1). Nothing calls the global `random`.
- **Bench output is files under `--out`**, one directory per bench run:
  - `runs/<system>/<pair>.json`
  - `summary.json`
  - `summary.md`
  - `flags/<pair>.jsonl`
  - `flag-summary.json`
  - `flag-summary.md`
  - `calibration.yaml`
  - `tiers.calibrated.yaml`
  - `ab-sheet.csv` and `ab-key.csv`.

  File names use the pair written `en-es` (a `>` is not safe in every file system); the summaries show `en>es`.
- **Language codes:** the bench config and outputs use BCP-47 tags (`en`, `es`, `zh-Hant`, `pt-BR`). FLORES codes (`spa_Latn`) appear only inside `coglossa/bench/flores.py`.

## Review Focus

These are the failure modes most likely to bite someone running bench that no task's main tests exercise. Each has its test in the task named.

1. **A model server failing mid-run** (a timeout on one pair after hours of work) must not lose the finished pairs. The failed (system, pair) is recorded with its error, the rest continue, and a second `bench run` redoes only what failed. Task 6, `test_a_failed_pair_is_recorded_and_rerun`.
2. **A translator merging sentences across paragraphs** must produce merged units scored against the joined references, never a crash or misaligned scores. Task 5, `test_merged_paragraphs_form_one_unit`.
3. **Language tags with a script or region** (`zh-Hant`, `pt-BR`, `zh-TW`) map to the right FLORES file. An unknown tag fails in one line that names the closest known tags. Task 3, `test_tags_with_script_or_region` and `test_unknown_tag_suggests`.
4. **Units too long for MetricX** (`scoring.qe_max_chars`) get `metricx: null`, are counted in the summary as unscored, and are never truncated. Task 6, `test_over_long_units_are_not_scored`.
5. **Calibration on too little data** (a tier with a handful of spans) keeps the current threshold for that tier and says why. Absurd thresholds fitted to three points are never suggested. Task 10, `test_small_tiers_keep_the_current_threshold`.

## Decisions this plan makes (for review)

- **The literary long-form dataset is deferred.** Spec §9.2 names "public-domain literary works with published translations". Aligning such works by paragraph is a project of its own. M6 ships FLORES-200 and a generic `parallel` dataset kind (two files aligned line by line), so a literary pair can be added as data later without code. Recorded as a spec deviation.
- **Real-model calibration needs real models.** Tasks 1–11 are fully testable offline with the synthetic model and scorer. Task 12 runs bench on real models and updates the shipped default thresholds and `tiers.yaml` from the results. It needs an OpenAI-compatible endpoint serving real models; the controller asks the user for one before dispatching it. Without one, the defaults stay marked provisional and customers calibrate on site with the same tool.
- **Tier cut-offs.** A pair's suggested tier comes from a chosen system's mean MetricX-24 reference score on FLORES devtest (0–25, lower is better): A ≤ 5.0, B ≤ 10.0, otherwise C. Both cuts are bench config settings.
- **"Caught" means a meaning-side flag for meaning errors, and `style_drift` for register shifts.** The meaning-side flags are `low_meaning`, `possible_omission` and `terminology_violation`. `agent_disagreement` and `cultural_or_wordplay` are not counted, because the injected spans have no translator candidates.

def _first_error(e: ValidationError) -> str:
    """One line for an operator (spec: every message is one line): the first problem with its

    errors = e.errors()

    buf = io.BytesIO()
    with tarfile.open(fileobj=buf, mode="w:gz") as tar:

            raw = text.encode()
            info = tarfile.TarInfo(name)
            info.size = len(raw)
            tar.addfile(info, io.BytesIO(raw))
    return buf.getvalue()

FLORES_URL = "https://dl.fbaipublicfiles.com/nllb/flores200_dataset.tar.gz"
FLORES_SHA256 = "<the SHA-256 from Step 2>"

_BY_TAG = {tag.lower(): code for code, tag in FLORES_CODES.items()}


def flores_code(tag: str, available: Iterable[str]) -> str:
    """The FLORES file code for a BCP-47 tag: exact tag, then language+script (a region
    implies a script for Chinese: zh-TW -> zh-Hant), then the bare language."""
    codes = set(available)
    parts = tag.replace("_", "-").lower().split("-")
    lang = parts[0]
    script = next((p for p in parts[1:] if len(p) == 4), None)
    region = next((p for p in parts[1:] if len(p) == 2), None)
    if script is None and region in _REGION_SCRIPT and lang == "zh":

    if lang == "zh" and script is None:
        candidates.append("zh-hans")
    for candidate in candidates:
        code = _BY_TAG.get(candidate)
        if code in codes:
            return code
    here = sorted(FLORES_CODES[c] for c in codes if c in FLORES_CODES)
    close = difflib.get_close_matches(tag, here, n=3, cutoff=0.0)
    raise ConfigError(
        f"no FLORES-200 data for language '{tag}' (in this copy); did you mean: "
        f"{', '.join(close)}? Languages here: {', '.join(here)}"
    )

```python
"""chrF (Popović 2015) with sacrebleu's defaults: character n-grams of order 1-6, beta 2,
whitespace ignored, no word n-grams. Implemented here so the engine needs no extra dependency;
the tests pin it to sacrebleu 2.4.3's values (spec §9.2)."""

from collections import Counter
from collections.abc import Sequence

ORDER = 6
BETA = 2.0


def _ngrams(text: str, n: int) -> Counter[str]:
    chars = "".join(text.split())
    return Counter(chars[i : i + n] for i in range(len(chars) - n + 1))


def _stats(hyp: str, ref: str) -> list[tuple[int, int, int]]:
    """Per order: (matching n-grams, hypothesis n-grams, reference n-grams)."""
    out = []
    for n in range(1, ORDER + 1):
        h, r = _ngrams(hyp, n), _ngrams(ref, n)
        out.append((sum((h & r).values()), sum(h.values()), sum(r.values())))
    return out


def _score(stats: list[tuple[int, int, int]]) -> float:
    precisions, recalls = [], []
    for match, hyp_total, ref_total in stats:
        if hyp_total > 0 and ref_total > 0:
            precisions.append(match / hyp_total)
            recalls.append(match / ref_total)
    if not precisions:
        return 0.0
    p, r = sum(precisions) / len(precisions), sum(recalls) / len(recalls)
    if p + r == 0:
        return 0.0
    b2 = BETA**2
    return 100 * (1 + b2) * p * r / (b2 * p + r)


def sentence_chrf(hypothesis: str, reference: str) -> float:
    return _score(_stats(hypothesis, reference))


def corpus_chrf(hypotheses: Sequence[str], references: Sequence[str]) -> float:
    if len(hypotheses) != len(references):
        raise ValueError("hypotheses and references must have the same length")
    totals = [[0, 0, 0] for _ in range(ORDER)]
    for hyp, ref in zip(hypotheses, references, strict=True):
        for k, (m, h, r) in enumerate(_stats(hyp, ref)):
            totals[k][0] += m
            totals[k][1] += h
            totals[k][2] += r
    return _score([tuple(t) for t in totals])
```

sacrebleu averages precision and recall over the orders that have n-grams, which is what `_score` does. It also has an effective-order rule for orders with no n-grams. If a pinned value disagrees, read sacrebleu's `CHRF._compute_f_score` / `_compute_score_from_stats` for version 2.4.3 and match it exactly, then note the detail in the module docstring.

```python
"""A FLORES sentence is one paragraph of the bench document. Translators may merge sentences
across paragraphs, so outputs are compared per unit: a maximal run of paragraphs joined by
spans. Most units are one sentence."""

from collections.abc import Sequence
from dataclasses import dataclass
from pathlib import Path

from coglossa.schema import Block, Segment


@dataclass(frozen=True)
class Unit:
    first: int  # 0-based sentence index, inclusive
    last: int
    text: str


def write_source_document(sentences: list[str], directory: Path) -> Path:
    directory.mkdir(parents=True, exist_ok=True)
    path = directory / "source.txt"
    paragraphs = [" ".join(s.split()) for s in sentences]
    path.write_text("\n\n".join(paragraphs) + "\n", encoding="utf-8")
    return path


def group_units(
    spans: Sequence[tuple[str, str, str]], segments: list[Segment], blocks: list[Block], n: int
) -> list[Unit]:
    if len(blocks) != n:
        raise ValueError(f"the bench document has {len(blocks)} paragraphs for {n} sentences")
    block_index = {b.id: k for k, b in enumerate(blocks)}
    seg_block = {s.id: block_index[s.block_id] for s in segments}
    groups: list[list] = []  # [first, last, texts]
    for start, end, text in spans:
        a, b = seg_block[start], seg_block[end]
        if groups and a <= groups[-1][1]:
            groups[-1][1] = max(groups[-1][1], b)
            groups[-1][2].append(text)
        else:
            groups.append([a, b, [text]])
    return [
        Unit(first, last, " ".join(t.strip() for t in texts if t.strip()))
        for first, last, texts in groups
    ]
```

**Precondition:** the controller confirms with the user, before dispatching, that OpenAI-compatible access to real models is available, and passes its details in the dispatch, never in a committed file. - [ ] **Step 1: Run bench on real models**

1. **Fetch FLORES.** Run `make flores`.
2. **Write the bench config.** Use FLORES devtest, 100 sentences per pair, seed 1. The pairs cover every tier: high-resource `en>es`, `en>zh-Hans`, `en>ru`, `en>fr`, `en>de`, `en>ja`; mid `en>ar`, `en>hi`, `en>tr`, `en>vi`, `en>uk`, `en>id`; low `en>sw`, `en>yo`, `en>am`, `en>ne`, `en>km`, `en>ha`. Add the reverse direction for three of them: `es>en`, `ar>en`, `sw>en`. The systems are:
   - a pipeline system with Qwen3 translators and a Gemma 3 judge and roundtrip
   - the mirror: Gemma 3 translators with a Qwen3 judge and roundtrip
   - a single-model baseline for each family.
3. **Get the scorer.** MetricX reference mode comes from a local scorer on the real weights: `docker run` the scorer image with `~/coglossa-weights` mounted, as in M5.
4. **Run.** `coglossa bench run`, then `bench flags` (with the injector set to the stronger model), then `bench calibrate`. Stop and report if the cost or time estimate after the first pair exceeds what the dispatch allows.
